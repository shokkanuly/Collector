# CLAUDE.md — Collector

Instructions for Claude Code working in this repo. Read this first, then the doc for the area you touch.

## What this project is

Collector recognizes the 24 static ASL fingerspelling letters from a webcam (MediaPipe → 21 landmarks → PyTorch NN, 87.9% test accuracy). See `README.md` and `ROADMAP.md`.

**Current milestone: hardware.** A servo-driven robotic hand, controlled by an Arduino, that signs letters with a physical hand. It connects to the existing software over USB serial. Design and plan:

- `docs/hardware/ARCHITECTURE.md`: system design, modules, data flow, decisions. **Source of truth.**
- `docs/hardware/PROTOCOL.md`: the serial contract between Python and firmware.
- `docs/hardware/ROADMAP.md`: staged tasks with "done when" criteria. Work one stage at a time.
- `docs/hardware/WIRING.md` + `wiring.svg`: every wire, BOM, Arduino pin and library details, power budget.
- `blender/build_collector_hand.py`: 1:1 3D model with all 26 letters keyframed (visual reference for poses; keep its pose table in sync with `hand/poses.json`).

## Hard rules

1. **The recognizer must work with no hardware attached.** Everything under `hand/` is optional: `pyserial` is imported lazily, and `app_opencv.py` behaves exactly as today unless `--hand` is passed.
2. **Never block the camera loop on serial I/O.** The hand runs on its own thread with a size-1 "latest wins" queue (same pattern as `speech_worker`).
3. **Do not modify** `best_model.pth`, `random_forest.joblib`, `label_map.joblib`, `hand_landmarker.task`, or existing rows of `landmarks_dataset.csv`. The hardware work reads the dataset and never writes to it.
4. **One pose source of truth:** `hand/poses.json`, generated by `scripts/build_poses.py` from the dataset plus `hand/pose_overrides.json`. Firmware does not hard-code letter poses; it receives angles. (The only exception is the standalone demo table described in PROTOCOL.md §5, which is generated from the same file.)
5. **Servo safety lives in two places.** Python clamps to `config/hand.yaml` limits, and the firmware clamps again with its own compiled-in limits. Never remove either.
6. **Protocol changes** require updating `docs/hardware/PROTOCOL.md`, the Python codec, the firmware parser, and their tests in the same commit.
7. Keep `test_pipeline.py` green, and add hardware tests under `tests/hand/`. Every test must pass with no Arduino connected (use `MockLink`).
8. Commit after each roadmap step, with a message that references the stage (e.g. `hand: stage 2 — kinematics + tests`).

## Commands

```bash
pip install -r requirements.txt            # ML stack
pip install -r requirements-hand.txt       # pyserial, pyyaml (hardware extras)
python test_pipeline.py                    # existing tests
python -m pytest tests/hand -q             # hardware tests (no Arduino needed)
python scripts/build_poses.py              # dataset → hand/poses.json + report
python scripts/hand_cli.py --mock spell HELLO   # dry run, prints frames
python scripts/hand_cli.py --port /dev/tty.usbmodem1101 pose A
python app_opencv.py --hand /dev/tty.usbmodem1101 --hand-mode letter
arduino-cli compile --fqbn arduino:avr:uno firmware/collector_hand
```

## Style

Python 3.9+, type hints on public functions, dataclasses for value objects, no global mutable state outside `app_opencv.py`. Units go in the names (`angle_deg`, `curl_01`). Firmware uses C++ as supported by Arduino AVR; no `String` class in the hot path (use fixed char buffers).

## When unsure

Check ARCHITECTURE.md §10 (open decisions). If the question is there, ask the user rather than guessing. Hardware choices (servo model, hand design) are the user's call.
